# Vibe Coding 工作流 v1.0

> **使用说明**：本文档是方法论文档，描述“怎么做”。各项目应在 `CLAUDE.md` 中引用本文档，项目状态由 AI 自动维护。

---

## 工作流概述

以 AI 协同为核心的完整开发流程，通过结构化步骤确保项目从需求到交付的高效执行。

---

## 核心流程（6步完整版）

### 阶段一：需求对齐与规范

#### 1. 需求讨论与明确

**目标**：与 AI 进行深度需求讨论，确保目标清晰

**执行步骤**：
- 与 AI 讨论项目需求，明确以下关键信息：
  - 项目目标和预期成果
  - 功能边界和限制条件
  - 技术栈选择和约束
  - 时间节点和里程碑
- 讨论要点：确保双方对需求的理解完全一致

**模式要求**：切换为 `Plan 模式`（AI 不自动执行，仅提供计划）

**产出**：讨论记录存入 `docs/project-spec/discussions/YYYY-MM-DD-主题.md`，并更新 `CLAUDE.md` 中的项目信息

#### 2. 需求文档化

**目标**：将讨论结果转化为结构化文档

**执行步骤**：
- 根据讨论结果编写/更新 `requirements.md`
- 文档应包含：
  - 项目概述和目标
  - 技术架构说明
  - 功能需求列表（带优先级 P0/P1/P2）
  - 功能依赖关系
  - 开发规范和标准
  - 非功能性需求（性能、安全、兼容性等）

**产出**：`docs/project-spec/requirements.md`

---

### 阶段二：功能框架规划

#### 3. 功能架构分析

**目标**：将项目拆分为可管理的功能模块，优化需求文档

**执行步骤**：
- 使用辅助工具进行项目功能头脑风暴
- 列写功能框架分布：
  - 核心功能模块（必须实现）
  - 辅助功能模块（锦上添花）
  - 功能依赖关系
  - 开发优先级
- 对每个功能模块进行深度拷问分析：
  - 这个功能解决什么问题？
  - 有什么边界条件？
  - 有什么潜在风险？
  - 需要什么外部依赖？
- 根据分析结果同步修改 `requirements.md` 和 `CLAUDE.md`

**模式要求**：可切换为 `Yolo 模式`

**产出**：更新后的 `requirements.md` 和 `CLAUDE.md`

---

### 阶段三：代码生成与实现

#### 4. 功能开发执行

**目标**：按照功能优先级，生成具体计划并执行功能编写

**执行步骤**：
- 按功能优先级顺序进行开发（P0 → P1 → P2）
- 调用 AI 自动生成功能代码
- 每个功能模块的开发流程：
  1. 读取上下文（项目状态、已有代码、requirements.md）
  2. 生成功能实现代码
  3. 代码质量检查
  4. 功能测试验证
  5. Git 提交（**仅在以下情况执行**，见下方备份策略）
  6. 更新 `CLAUDE.md` 中的功能进度

**产出**：功能代码 + 单元测试

---

#### Git 备份策略（替代频繁提交）

为避免 Git 历史过于碎片化，只在 **重大变更前** 或 **用户明确要求** 时进行提交。

| 场景 | 是否 Git 提交 | 说明 |
|------|--------------|------|
| 日常功能开发（P1/P2） | ❌ 不提交 | 代码保存在本地工作区即可 |
| 完成一个完整的 P0 核心功能 | ✅ 提交 | 确保核心功能可回滚 |
| 进行大规模重构/删除代码前 | ✅ 提交 | 作为备份点，方便回退 |
| 用户明确说“提交代码” / “备份一下” | ✅ 提交 | 尊重用户指令 |
| 阶段性里程碑（如版本发布前） | ✅ 提交 | 打 tag 或普通 commit |

**AI 行为规则**：
- 默认情况下，AI **不会**在每次功能完成后自动执行 `git commit`
- 当遇到上述需要提交的场景时，AI 应主动询问：“当前已完成 `[功能名]`，建议进行 Git 备份，是否确认提交？”
- 用户回复“是”或“提交”后再执行 Git 操作
- 用户可随时用指令 `git backup` 或 `保存快照` 触发提交

**提交规范**（当执行提交时）：
git add .  
git commit -m "checkpoint: 完成 `[功能名]` - `[日期]`"  
git push（可选）

---

### 阶段四：测试优化与问题处理

#### 5. 项目测试与优化

**目标**：确保项目质量和稳定性

**执行步骤**：
- 全面测试项目功能
- 发现问题时进行针对性优化：

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 问题描述优化 | 用 LLM 优化问题描述 |
| 2 | 问题确认 | 明确复现步骤和条件 |
| 3 | 范围确定 | 明确修改范围和目标 |
| 4 | 代码备份 | Git 备份正常代码 |
| 5 | 问题修复 | 让 AI 按优化描述修改 |
| 6 | 验证修复 | 确认问题解决 |

- 发现问题时添加到 `CLAUDE.md` 的待办事项
- 问题解决后更新状态

---

### 阶段五：项目归档

#### 6. 项目完成与归档

**目标**：完成项目并做好归档工作

**执行步骤**：
- 确认所有功能正常工作
- 项目文档完善
- 最终 Git 提交并推送
- 更新 `CLAUDE.md` 中的项目状态为「已完成」

**产出**：完整的项目交付物

## 辅助机制

### 问题描述优化策略
**适用场景**：复杂修改问题
**执行步骤**：
1. 将报错有出入情况描述输入 LLM 优化
2. 确认优化后的描述准确
3. 明确修改范围和目标
4. 执行修改

### 重复操作处理策略

| 类型 | 特点 | 处理方式 |
|------|------|----------|
| 简单重复 | 模式固定，上下文相关 | AI 直接按约定执行 |
| 复杂重复 | 需要标准化流程 | 制作成 Skill |

## CLAUDE.md 自动维护规则

AI 在以下情况应自动更新项目的 `CLAUDE.md`：

| 触发事件 | 更新内容 |
|----------|----------|
| 需求讨论完成 | 项目名称、描述、技术栈 |
| 功能拆解完成 | 功能进度表（P0/P1/P2） |
| 完成一个功能 | 移动功能到「已完成」 |
| 发现问题 | 添加到「待办事项」 |
| 解决问题 | 从待办事项移除 |
| Git 配置完成 | 仓库地址 |
| 阶段切换 | 当前阶段 |

## 工作流优势

| 优势 | 说明 |
|------|------|
| 结构化开发 | 清晰阶段划分，避免混乱 |
| AI 协同优化 | 充分利用 AI 能力 |
| 质量保证 | 多轮测试，标准化问题处理 |
| 效率提升 | 重复操作智能处理 |
| 文档自动化 | AI 自动维护项目状态 |

---

## 最佳实践

1. **需求阶段**：花足够时间讨论，确保理解一致
2. **规划阶段**：深度分析每个功能模块
3. **开发阶段**：小步快跑，及时测试
4. **优化阶段**：善用 LLM 优化问题描述
5. **文档维护**：让 AI 自动更新 CLAUDE.md，保持同步

## 快速参考

### 简单项目流程
1. 需求讨论（Plan 模式）
2. 编写 requirements.md
3. 让 AI 写代码
4. Git 提交
5. 测试 → 有问题让 AI 改

### 复杂项目流程
1. 深度需求讨论（Plan 模式）
2. 编写 requirements.md
3. 功能架构分析（Yolo 模式）
4. 让 AI 写实现计划
5. 按计划分步执行
6. 代码审查
7. 测试优化
