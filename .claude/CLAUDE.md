## 模式切换

> 快捷键：Shift + Tab 切换模式

| 模式 | 行为 |
|------|------|
| **自动模式** | AI 根据需要自动执行 |
| **Plan 模式** | 仅提供计划，用户确认后执行 |
| **Yolo 模式** | 直接执行，不确认 |

### 工作流推荐模式

| 阶段 | 推荐模式 |
|------|----------|
| 需求讨论 | Plan 模式 |
| 架构分析 | Yolo 模式 |
| 代码开发 | 自动模式 |
| 问题修复 | Plan 模式（复杂）/ 自动模式（简单） |

## 代码规范

### Git Commit 格式
```
<type>: <subject>

[optional body]

**Type 类型**：
- `feat`: 新功能
- `fix`: 修复 bug
- `docs`: 文档更新
- `style`: 代码格式
- `refactor`: 重构
- `test`: 测试相关
- `chore`: 构建/工具链

**示例**：
feat: 添加用户登录功能
- 实现 JWT token 生成
- 添加登录 API 接口

```

## AI 自动维护规则

AI 在以下情况应自动更新本文件：

| 触发事件 | 更新内容 |
|----------|----------|
| 需求讨论完成 | 项目名称、描述、技术栈 |
| 功能拆解完成 | 功能进度表 |
| 开始开发一个功能 | 状态改为「开发中」 |
| 完成一个功能 | 移到「已完成功能」 |
| 发现问题 | 添加到「待办事项」 |
| 解决问题 | 从待办事项移除 |
| Git 配置完成 | 更新仓库地址 |
| 阶段切换 | 更新当前阶段 |

### 更新方式

使用文件编辑工具直接修改本文件中对应字段的值。

## 注意事项

1. 需求阶段必须先讨论清楚再写代码
2. 每个功能完成后必须测试
3. 保持小步提交，每次提交都应该是可运行状态
4. 遇到复杂问题时，先用 Plan 模式讨论方案
